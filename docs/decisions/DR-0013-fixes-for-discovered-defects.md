# DR-0013: Fixes for defects found while building the mutation checks and the owed probes

- Status: proposed (owner acceptance and signature pending; the builder cannot accept its own record)
- Date: 2026-10-13
- Rules: TENANT-1, AUTH-1, AUTH-2, AUTH-4, BILL-2, VERIFY-3

## Context
Reviews and runs during Phase 4 found defects that were recorded as known limits (DR-0009, DR-0012) or reported by reviewers but not fixed. One was confirmed by running it: against an app with no billing routes, the verifier reports `FAIL BILL-2 forged-signature` and "1 confirmed finding(s)", so an absent feature is reported as a security finding. This record lists the fixes, made with the same split of roles as before: the verifier and spec edits (frozen paths) by a separate attacker session, the auth test and the scripts by the builder.

### Edits to frozen paths (`packages/verify/`, `packages/spec/src/formats.ts` comments)
A third probe outcome, "not applicable", used by `forged-signature` only when both `GET /plan` and a forged `POST /webhooks/billing` are 404; stronger `role-change-authority`, `listings-hide-secrets` and `key-wrong-secret-denied`; one seeded bug for the secret-length case; three comment corrections.

## Decision
1. **A missing feature is "not applicable", never a finding and never a pass.** A probe may report `skipped` with a reason; skipped probes are listed, are not findings, do not count towards rule coverage or the run's probe count, the final summary line says how many were not applicable, the event log never records a run that verified nothing as passed, and a run in which every selected probe was skipped exits non-zero. Check: `test:packages/verify/test/verify.test.ts::a probe that does not apply`, `test:packages/verify/test/verify.test.ts::a run that verified nothing`, `test:packages/verify/test/verify.test.ts::a target that serves the webhook but not GET /plan is not skipped`, `test:packages/verify/test/verify.test.ts::the run log and CLI summary agree with what was actually verified`.
2. **Probes that could be satisfied by another defence now carry a positive control or a wider scan.** `role-change-authority` first shows the same cookie can perform an allowed write; `listings-hide-secrets` also rejects any 64-hex string, any `pbkdf2-sha256$` hash and any 43-character base64url token; `key-wrong-secret-denied` also tries first-character, middle-character, truncated and extended secrets, each backed by a seeded bug that only the new behaviour catches (`key-secret-length-ignored`, `admin-user-create-refused`, and two leaks in neutrally named fields that the old fixed-word scan cannot see). Check: `probe:role-change-authority`, `probe:listings-hide-secrets`, `probe:key-wrong-secret-denied`, `mutation:user-list-leaks-password-hash`, `test:packages/verify/test/verify.test.ts::the listing secret-shape checks catch leaks the old needle list cannot see`.
3. **The dummy password hash is tied to the real work factor.** The constant is exported and the test asserts the dummy's iteration count equals it, so raising one without regenerating the other fails. Check: `test:packages/auth/test/auth.test.ts::unknown-user login verifies against a well-formed constant hash`.
4. **The mutation runner copies no secrets files, checks every edit when it is applied, and judges gaps by real test failures.** Secret-bearing files (`.dev.vars`, `.env*`, `.npmrc`, `*.pem`, `*.key`) are left out of the scratch copy, so a scratch directory left behind by an interrupted run holds none (the script is synchronous, so it cannot clean up on a signal, and it installs no signal handlers because that would make Ctrl-C and a timeout's SIGTERM do nothing); every edit of a multi-edit mutation must match exactly once at the moment it is applied; a gap counts as killed only by a failing test, not by a crash or syntax error, judged by the test runner's failure count and a check of its output for crash signatures. That check can class a genuine failure whose output mentions a syntax error as a crash, which fails safe (the gap then reads as surviving). Check: `script:scripts/mutation-selfcheck.ts`, `gate:phase4`.
5. **Comments that claimed unbuilt things as planned, or misdescribed what exists, are corrected.** No check: comment text has no behaviour to test.

## Consequences
`gate:phase4` is unchanged in shape. Known limits that remain are listed in DR-0009 and DR-0012; this record closes the verifier false finding, the three weak-probe notes, the dummy-hash coupling and the runner robustness items. A green report means no known leak paths, not proof of none.
