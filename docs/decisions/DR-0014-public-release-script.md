# DR-0014: Public release by script: a clean export to a separate repository, then npm

- Status: proposed (owner requested this design in session on 2026-10-13; acceptance and signature pending for this record)
- Date: 2026-10-13
- Rules: TENANT-1, AUTH-1, AUTH-2, AUTH-3, AUTH-4

## Context
The owner wants the public repository (`github.com/kalahroudi/bulkhead-oss` by default; the private one is `kalahroudi/bulkhead`, so the public repository needs another name, and `--repo owner/name` overrides it) and the npm packages to contain nothing private: no internal documents, specifications, decision records, or traces of how the project is built. The release is run by hand with a version argument, and it must create `main` when the public repository has none. The private repository keeps its history, records and process; the public one is a clean export with its own README, changelog and site.

Two hostile reviews shaped this record. A string scan passed at first, yet the public spec package still shipped the project's internal workflow as API and the machine's git identity would have authored the public history. A second pass then found that the machine's git configuration (a tool signing key, template hooks) could still reach the commit, that a second release could destroy outside work on `main`, that npm checks came after the irreversible push, and that the scan had blind spots. This is the corrected design.

## Decision
1. **Export by allowlist, then exact text fixes, then a scan that reads everything.** Only the four packages, the demo app, a few scripts and named root files are copied from the committed tree. Roadmap and process wording in shipped comments is replaced by exact find-and-replace fixes that must match exactly once. The scan reads every exported file as text, flags binaries and unknown file types as unscannable, and matches phase and roadmap wording case-insensitively. The allowlist is by directory for the packages, so a new file inside them ships and is covered by the scan, not by exclusion. The exact file list and tree are fixed in a snapshot taken right after the scan, before install and the gate run; only those files are copied into the public commit, the staged files must equal that list, the staged tree is scanned again, and its tree id must equal the snapshot's, so a file that changes or appears afterwards cannot ship. Check: `test:scripts/release-selftest.ts::not shippable`, `test:scripts/release-selftest.ts::a fix that no longer matches aborts the export`, `test:scripts/release-selftest.ts::a fix that matches more than once aborts the export`, `test:scripts/release-selftest.ts::the scan reads every file type`, `test:scripts/release-selftest.ts::a file that changed after the scan is re-scanned`, `test:scripts/release-selftest.ts::files that appear after the snapshot`.
2. **The public spec package describes what exists today.** The catalog keeps the tenancy, route, auth, boot and webhook-signature rules and drops the internal process rules and every rule for an unbuilt feature (crypto, billing adapters, domains, HTTP hardening, lifecycle); ROUTE-3 is reworded, not left as a gap; the internal `principle` field, the classification, decision-record and attestation formats, the decision linter, and the agent and review event types do not ship; the public test file is a template. A restructured source aborts the export. Check: `test:scripts/release-selftest.ts::public catalog has only product-guarantee rules that exist today`, `test:scripts/release-selftest.ts::the public catalog has no gap`, `test:scripts/release-selftest.ts::public formats keep findings and events`, `test:scripts/release-selftest.ts::a restructured catalog aborts the export`.
3. **A leak scan runs on the exported tree and on the packed tarballs,** over contents and paths, and fails on any private path, record id, roadmap or phase wording, private URL, tool or session provenance, process wording, unfinished owner TODO, or citation of a rule id that is not in the catalog the package itself ships. Check: `test:scripts/release-selftest.ts::scan catches`, `test:scripts/release-selftest.ts::real export has no private material`, `test:scripts/release-selftest.ts::a tarball with source`, `test:scripts/release-selftest.ts::a tarball citing a rule`.
4. **The public history carries the releaser's identity and nothing from the machine.** The script refuses a tool identity, takes `--author`, sets author, committer and tagger explicitly, and creates the commit and tag with the global and system git configuration disabled, template hooks off, user-level ignore and attributes files off, and signing off unless `--sign` is passed (which really requests a signature and fails if none can be made). The message is written verbatim. It then reads the commit and tag objects back and refuses to push if they carry another identity, a signature that was not asked for, or an altered message. Check: `test:scripts/release-selftest.ts::a tool git identity is refused`, `test:scripts/release-selftest.ts::the public commit carries the releaser's identity`, `test:scripts/release-selftest.ts::a tool signing key, tool identity and trailer-adding hook`, `test:scripts/release-selftest.ts::the read-back refuses a commit that carries another identity`, `test:scripts/release-selftest.ts::the read-back refuses a signature nobody asked for`, `test:scripts/release-selftest.ts::the read-back refuses an altered message`, `test:scripts/release-selftest.ts::the read-back runs before the push`, `test:scripts/release-selftest.ts::--sign asks for a signature`, `test:scripts/release-selftest.ts::the commit message is stored verbatim`, `test:scripts/release-selftest.ts::global git ignore file does not drop files`.
5. **Branch and tag land together, never forced, and `main` is a mirror.** One atomic push; `main` is created when missing; exact ref lookup, so `feature/main` is not `main`; tag annotations keep the changelog headings. Any commit on `main` that this tool did not write is listed and refused unless `--adopt-existing` is passed, and the files that would be removed are named in the plan printed before the confirmation prompt. Commits made on the public repo by others are overwritten by the next release by design; worthwhile ones are to be ported into the private repo first. With `--adopt-existing` the kept history is itself checked for tool identities and private material, and the private repository is refused as a target in every spelling. Check: `test:scripts/release-selftest.ts::first release creates main and the tag together`, `test:scripts/release-selftest.ts::a branch named feature/main`, `test:scripts/release-selftest.ts::a later outside commit is named`, `test:scripts/release-selftest.ts::the tag is unsigned, by the releaser, and keeps the changelog headings`, `test:scripts/release-selftest.ts::--adopt-existing still refuses history that carries a tool identity`, `test:scripts/release-selftest.ts::the private repository is refused as a target`.
6. **The tarballs tested are the tarballs published, and the registry is checked.** They are packed once, scanned, handed to the consumer test through `CONSUMER_TARBALL_DIR`, hash-checked before publishing, and published from the same files, with the version and dist-tag verified inside each tarball. There is no way to skip these checks on a real release. A rerun after a partial npm failure (`--skip-git`) first proves the public tag holds exactly the tree being published. Check: `script:scripts/consumer-test.ts`, `script:scripts/release.ts`, `test:scripts/release-selftest.ts::skip-git rerun: a different export is refused`.
7. **npm is checked before anything irreversible, and verified after.** Before the git push the script requires `npm whoami`, runs `npm publish --dry-run` for every package, and refuses if a package at this version is already on npm with different bytes. After each publish it confirms the registry serves the same integrity as the tested tarball. npm prompts for the one-time code at each publish, so none is ever passed on a command line, and every temporary copy that could hold a credential is removed when the command ends, including on Ctrl-C. No check: these steps need a real registry and login, so only an actual release exercises them; the dry run covers the preflight.
8. **Versions are strict semver and dist-tags are safe.** No leading zeros or empty identifiers; a prerelease label must be a lowercase word that is not `latest`, and becomes the npm dist-tag (`0.1.0-preview.N` publishes under `preview`, so every install command in the docs carries `@preview`, and `npx` uses the scoped package name because `bulkhead-verify` alone is a different, unrelated package). The command rejects a malformed version and stops on a missing changelog section before exporting. Check: `test:scripts/release-selftest.ts::rejected version`, `test:scripts/release-selftest.ts::npm dist-tag from version`, `test:scripts/release-selftest.ts::the command rejects a malformed version`.
9. **There is no release workflow.** Publishing is only this script, run by the owner; provenance attestations need a hosted workflow and are therefore not claimed. The public repository gets a CI workflow and a Pages workflow only. No check: whether those two workflows run correctly on GitHub can only be observed there after the first push.

## Owner setup the script cannot do
The public repository exists (empty is fine); private vulnerability reporting is enabled (SECURITY.md depends on it); GitHub Pages source is set to GitHub Actions, after which the first failed Pages run is re-run; `npm login` as a member of the `@kalahroudi` scope with 2FA. Open questions for the owner: the GitHub owner and the npm scope are both `kalahroudi` (settled), and the public repository name `bulkhead-oss` is a default the owner may change with `--repo`; the Apache-2.0 `LICENSE` carries no copyright line or NOTICE; the workflow actions are pinned by major tag only; the verifier still ships a billing-webhook probe (BILL-2) although the preview has no billing, and the demo does not expose that route, so `run` is documented with a `--rules` list; npm scope membership is not checked before the push, only login and a publish dry run; dist-tags are not checked for going backwards when an older version is released later.

## Consequences
`gate:release` also runs `scripts/release-selftest.ts`. A string scan can only find what it was told to look for, so the owner should skim the first public commit before pushing; `--dry-run` produces exactly that tree and `--out` keeps it. The tool supports macOS and Linux. A green report means no known leak paths, not proof of none.
