# DR-0014: Public release by script: a clean export to a separate repository, then npm

- Status: proposed (owner requested this design in session on 2026-10-13; acceptance and signature pending for this record)
- Date: 2026-10-13
- Rules: TENANT-1, AUTH-1, AUTH-2, AUTH-3, AUTH-4

## Context
The owner wants the public repository (`github.com/flamingosh/bulkhead`) and the npm packages to contain nothing private: no internal documents, specifications, decision records, or traces of how the project is built. The release is run by hand with a version argument, and it must create `main` when the public repository has none. The private repository keeps its history, records and process; the public one is a clean export with its own README, changelog and site.

A first version scanned for known strings and passed. A hostile review then found what string scanning cannot: the public spec package still shipped the project's internal workflow as API (decision-record validators, attestation formats, agent and review event types), the git identity of the machine would have authored the public history, and several release-flow hazards. This record is the corrected design.

## Decision
1. **Export by allowlist, then exact text fixes.** Only the four packages, the demo app, a few scripts and named root files are copied from the committed tree; a new private file cannot ship by being added. Roadmap and process wording in shipped comments is replaced by exact find-and-replace fixes, each of which must match exactly once or the export aborts. Check: `test:scripts/release-selftest.ts::a fix that no longer matches aborts the export`, `test:scripts/release-selftest.ts::not shippable`.
2. **The public spec package carries product guarantees only.** The catalog is cut to the tenancy, route, auth, crypto, boot, billing, domain, HTTP and lifecycle rules (ROUTE-3 is reworded, not left as a gap, and the internal `principle` field is removed); the decision-record, attestation and agent or review event formats and the decision linter do not ship; the public test file is a template. A restructured source aborts the export. Check: `test:scripts/release-selftest.ts::the public catalog has no gap`, `test:scripts/release-selftest.ts::public formats keep findings`, `test:scripts/release-selftest.ts::a restructured catalog aborts the export`.
3. **A leak scan runs on the exported tree and on the packed tarballs,** over file contents and file paths, and fails on any private path, record id, roadmap phase, private URL, agent or process wording, unfinished owner TODO, or citation of a rule id that is not in the public catalog. Check: `test:scripts/release-selftest.ts::scan catches`, `test:scripts/release-selftest.ts::real export has no private material`, `test:scripts/release-selftest.ts::a tarball with source`.
4. **The public history carries the releaser's identity.** The script refuses a tool identity, takes `--author`, and sets author and committer explicitly for the commit and the annotated tag, overriding the environment. Check: `test:scripts/release-selftest.ts::the public commit carries the releaser's identity`, `test:scripts/release-selftest.ts::a tool git identity is refused`.
5. **Branch and tag land together, never forced.** One atomic push of `main` and the tag; `main` is created when missing; exact ref lookup, so `feature/main` is not `main`; an existing `main` that this tool did not write is refused unless `--adopt-existing` is passed, and the files that would be removed are listed. Check: `test:scripts/release-selftest.ts::first release creates main and the tag together`, `test:scripts/release-selftest.ts::a branch named feature/main`, `test:scripts/release-selftest.ts::an existing main written by someone else is refused`.
6. **The tarballs tested are the tarballs published.** They are packed once, scanned, handed to the consumer test through `CONSUMER_TARBALL_DIR`, hash-checked afterwards, and published from the same files, with the version and dist-tag verified inside each tarball. There is no way to skip the checks on a real release. A rerun after a partial npm failure (`--skip-git`) first proves the public tag holds exactly the tree being published. Check: `script:scripts/consumer-test.ts`, `script:scripts/release.ts`, `test:scripts/release-selftest.ts::skip-git rerun: a different export is refused`.
7. **Versions are strict semver and dist-tags are safe.** No leading zeros or empty identifiers; a prerelease label must be a lowercase word that is not `latest`, and becomes the npm dist-tag (`0.1.0-preview.N` publishes under `preview`, so every install command in the docs carries `@preview`, and `npx` uses the scoped package name because `bulkhead-verify` alone is a different, unrelated package). Check: `test:scripts/release-selftest.ts::rejected version`, `test:scripts/release-selftest.ts::npm dist-tag from version`.
8. **There is no release workflow.** Publishing is only this script, run by the owner; provenance attestations need a hosted workflow and are therefore not claimed. The public repository gets a CI workflow and a Pages workflow only. No check: whether the CI and Pages workflows run correctly on GitHub can only be observed there after the first push.

## Owner setup the script cannot do
The public repository exists (empty is fine); private vulnerability reporting is enabled (SECURITY.md depends on it); GitHub Pages source is set to GitHub Actions, after which the first failed Pages run is re-run; `npm login` as a member of the `@kalahroudi` scope with 2FA. Open questions for the owner: the npm scope `@kalahroudi` differs from the GitHub owner `flamingosh` (keep, or publish under a new scope, which renames every package); the Apache-2.0 `LICENSE` carries no copyright line or NOTICE; actions in the workflows are pinned by major tag only.

## Consequences
`gate:release` now also runs `scripts/release-selftest.ts`. The remaining private-process material that a string scan cannot see is whatever the allowlist includes by design (source code and its comments), so the owner should skim `git diff` of the first public commit before pushing; `--dry-run` produces exactly that tree. A green report means no known leak paths, not proof of none.
