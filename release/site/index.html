Multi-tenant security for Cloudflare Workers

Isolation enforced by structure, not discipline, and checked by a verifier that attacks your running app and never reads your code.

Preview. Not security-attested, no encryption at rest yet, no billing, no tenant provisioning (the first owner is claimed with a bootstrap secret). Do not put sensitive data in it. A green verify report means no known leak paths, not proof that none exist.

What you get

  • One tenant per hostname. The tenant comes from the host only, never from a header, query or body.
  • One database per tenant. Each tenant gets its own Durable Object SQLite database behind a scoped handle, so a query cannot name another tenant.
  • No route without a policy. Every route declares a role, permission or an explicit public reason, or the app refuses to start.
  • Users, sessions and API keys per tenant, with roles, permissions, immediate revocation and a same-origin check on cookie writes.
  • An independent verifier with probes for tenant isolation and auth, a self-check that proves it catches its own planted bugs, and a black-box run against a live app.

Quickstart

npm install @kalahroudi/bulkhead-core@preview @kalahroudi/bulkhead-auth@preview
npm install -D wrangler @cloudflare/workers-types

The complete wrangler.jsonc and src/index.ts, the commands to claim the first owner and sign in, and the production notes are in the README. That code is the tested quickstart: it is extracted from the README, typechecked against the published packages, and driven end to end on every release.

Verify

npx @kalahroudi/bulkhead-verify@preview selfcheck

Proves the verifier catches its own seeded bugs and raises no false alarms; it needs no app. bulkhead-verify run --target <url> attacks a running app, but today its probes expect a few probe-contract routes that only the demo app exposes; the README explains how to add them to a non-production copy of your app. A packaged helper is planned.

Not included yet

  • Encryption of sensitive fields at rest, and write-only secrets
  • Billing, and tenant provisioning (production tenants are rows you insert by hand today)
  • Password reset, email verification, MFA, SSO, a per-IP login throttle
  • An independent audit of the rules
